## What this session accomplished

### 1. Homepage icon audit + full replacement — page 302 (`home`)

**Problem**: Homepage had 24 `icon-box` widgets still on default `fas fa-search` (FontAwesome magnifying glass), 2 icon-boxes on `lucide-scroll` (wrong for their content), only 3 already using correct lucide SVGs. Source at kimi.page uses lucide-* icons with specific per-card mapping.

**Solution**:
- Scraped source homepage DOM via Playwright at `http://127.0.0.1:8099/` (local SPA serve, per §2 in HANDOFF)
- Extracted title → icon mapping (SVG `class="lucide lucide-*"` scoped to nearest card container)
- Extracted 17 missing lucide SVGs directly from source DOM (`outerHTML`), added `xmlns` attribute, saved as `svgs_new/lucide-*.svg`
- Uploaded 17 SVGs to WP media library via multipart (bypass ModSecurity, per G2). New media IDs 1882–1898.
- Patched `_elementor_data` for page 302, walked all `icon-box` widgets, matched title → target icon in library, wrote new `selected_icon: {value: {url, id}, library: 'svg'}`
- POST `/wp-json/wp/v2/pages/302` + cleared `_elementor_css` meta
- Verified via curl to homepage — 30/30 icon-boxes render inline lucide SVGs, 0 `fa-search` remaining

**Result**: 27 icons patched (24 fa-search + 2 wrong lucide + 1 verified), 3 already-correct left alone.

**Note on cache (G1)**: Homepage 302 does NOT get stuck like other pages when only icon changes are made, because Elementor inlines the SVG content directly into the rendered HTML (not just a URL reference). Icon changes to page 302 propagate to frontend immediately, no cache flush needed.

### 3. Footer tablet/mobile grid CSS

**Problem**: Astra footer builder's primary footer wrap uses `grid-template-columns: repeat(6, 1fr)` at both desktop AND tablet (Astra tablet breakpoint = 921px). At 834px iPad the 6 columns squeeze to ~130px each, wrapping "MANAGEMENT RESEARCH" to `MANAGEMEN\nT RESEARCH`.

**Iteration**:
- v1: broad selector using `.ast-builder-grid-row-container.ast-builder-grid-row-mobile-full` — caused CTA section "Ready to Turn Insights into Action?" to be forced to 2 columns on mobile, breaking word wrap on 30pt heading
- v2 (final): scoped to `[data-section="section-primary-footer-builder"]` attribute — only affects primary footer, leaves above-footer CTA + below-footer copyright/logo untouched

**Final CSS** (paste into Appearance > Customize > Additional CSS):

```css
/* Tablet: primary footer 6 columns -> 3 columns (2 rows of 3) */
@media (max-width: 921px) {
  .site-primary-footer-wrap[data-section="section-primary-footer-builder"] .ast-builder-grid-row {
    grid-template-columns: repeat(3, 1fr) !important;
    row-gap: 32px !important;
    column-gap: 24px !important;
  }
  .site-primary-footer-wrap .ast-header-html,
  .site-primary-footer-wrap .ast-builder-html-element,
  .site-primary-footer-wrap p,
  .site-primary-footer-wrap span,
  .site-primary-footer-wrap strong {
    word-break: normal !important;
    overflow-wrap: normal !important;
    hyphens: none !important;
    line-height: 1.7 !important;
  }
}

/* Mobile: primary footer -> 2 columns */
@media (max-width: 544px) {
  .site-primary-footer-wrap[data-section="section-primary-footer-builder"] .ast-builder-grid-row {
    grid-template-columns: repeat(2, 1fr) !important;
    row-gap: 24px !important;
  }
}
```

**Pending user action**: paste into Astra Customizer. Cannot apply via REST (see gotcha below).

## New gotcha discovered this session

### G8 — Astra Customize > Additional CSS has NO REST endpoint

Attempted and confirmed dead ends:
- `POST /wp/v2/astra-advanced-hook` — creates the post successfully with `layout=hooks` + `action=wp_head`, but display rules meta (`ast-advanced-headers-rules`, `ast-advanced-hook-users`) aren't registered for REST edit. WordPress silently drops those keys. Hook never renders on frontend.
- `POST /wp/v2/elementor_library/113 meta._elementor_page_settings.custom_css` — accepted the write but Elementor kit CSS file (`post-113.css`) doesn't regenerate to include the custom_css value. Elementor kit editor UI is the only trigger.
- `/wp-json/astra-addon/v1/custom-layouts` — only GET/DELETE registered, no POST/PUT.
- `/wp/v2/custom_css` — WP core post type not exposed to REST (`show_in_rest=false`).

**Fix**: deliver CSS to user as a file, user pastes manually. Adds a 30-second manual step per CSS iteration but is the only reliable path on this stack.
